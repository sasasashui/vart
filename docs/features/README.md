# Feature documentation

This directory contains focused descriptions of implemented subsystems and
independent features. Add or update a document with the code that introduces or
materially changes the feature.

A feature document should remain concise and normally contain:

- purpose and scope
- public interfaces and ownership
- important state and invariants
- guest-visible behavior or ABI
- interactions with other subsystems
- known limitations
- validation and test coverage

Planned ideas that do not yet constrain an implementation should remain in the
architecture document or issue tracker rather than appearing as implemented
feature documentation.
