# VART PCIe foundation audit

This audit records the PCIe hierarchy checkpoint for the current VART
development line.  It is a review boundary, not a claim that VART implements
the complete PCIe specification.

## Scope covered

The current implementation and tests cover:

- a RISC-V `virt`-compatible root complex and ECAM dispatch;
- root, secondary, and recursively nested PCI buses;
- type-0 endpoints, type-1 bridges, and a small switch topology;
- function-0/multifunction validation and recursive requester-ID updates;
- 32-bit, 64-bit, and prefetchable BAR allocation, probing, relocation, and
  bridge-window bookkeeping;
- Memory Space Enable and Bus Master Enable state transitions;
- function reset and deterministic MSI-X/BAR cleanup;
- PCI capabilities and MSI-X table/PBA access;
- basic level-triggered INTx delivery through the project interrupt API;
- DMA helpers that validate bus mastering and the caller's requester ID;
- virtio-blk and virtio-net endpoints behind the root bus and switch; and
- Linux 6.18.3 and 7.3-rc2 enumeration and networking checks.

The device-facing DMA address space remains attached to each device.  This is
the interface that the upcoming IOMMU work will replace with translated
accesses without changing virtio or future device code.

## Verification performed

The following checks passed on the RISC-V KVM host:

```text
make -j2 check
make check-linux-6.18.3-pcie-switch-net \
     check-linux-7.3-rc2-pcie-switch-net
```

The first command passed the PCI unit tests (`ecam`, `root-complex`,
`bridge`, `multilevel`, `switch`, `bars`, `multifunction`, `capability`,
`msix`, `msix-irq`, `intx`, and `dma`) as well as the KVM, virtio, and full
machine checks.  Both Linux checks booted, enumerated the switch topology,
and completed the virtio-net connectivity check.

## Deliberate limitations

The following features are outside this checkpoint:

- automatic INTx pin swizzling across bridges and APLIC wiring;
- complete MSI/MSI-X capability semantics for every device class;
- AER, power management, hotplug, ACS, SR-IOV, ATS, PASID, and migration;
- multiple PCI domains and a complete bridge resource forwarding algorithm;
- physical-device passthrough/VFIO; and
- a hardware-accelerated or KVM-in-kernel IOMMU path.

The minimal INTx path is sufficient for current tests, but a real PCIe
hierarchy must derive the parent interrupt pin from `(device, pin)` while
walking bridges.  That work belongs to the interrupt/IOMMU follow-up and must
not be inferred from the current direct `VartIrq` connection.

## Checkpoint

The commits through `295c765` are the reviewed PCIe foundation.  The
checkpoint tag is `v0.2.0-pcie-foundation`.  Changes after this tag should be
kept separate so that IOMMU experiments cannot silently change the validated
PCIe baseline.
