# VART 0.1.0 milestone audit

## Baseline

The annotated `v0.1.0` tag identifies commit `8b3735a`, the completion of
Stages 1 through 9. The audit was performed on a RISC-V host running Linux
6.18.3 with GCC 15.2.0. Audit documentation is intentionally committed after
the immutable release tag.

## Verified behavior

Fresh normal and `CONFIG_DEBUG_LOCKS=y` builds were created in independent
directories. Both completed the full `make check` suite, including unit tests,
tiny guest tests, KVM capability and register tests, SMP execution, SBI, AIA,
UART receive interrupts, coordinated signals, and runtime failure cleanup.

The Linux matrix additionally passed:

- Linux 6.18.3 boot and initramfs userspace;
- Linux 6.18.3 interactive pipe console;
- Linux 6.18.3 controlling-PTY input, output, Ctrl-C, and terminal restore;
- Linux 7.3-rc2 with two vCPUs; and
- repeated boot and PTY cleanup tests.

Repository checks found no tracked build products, object files, guest
binaries, oversized artifacts, whitespace errors, Git object corruption, or
unresolved `TODO`, `FIXME`, or `HACK` markers. Root build-directory variants
are ignored so isolated audit and sanitizer builds do not dirty the worktree.

## Documentation findings

The pre-audit README still described OpenSBI loading and SMP as future work.
That information predated the direct S-mode KVM contract and completed SMP
implementation. The post-tag documentation update replaces it with the exact
0.1.0 machine, build, run, validation, and limitation descriptions.

Important investigations are retained under `docs/debugging/`: RISC-V KVM HSM
error propagation, secondary MP state, Linux userspace ISA selection, stale
objects after header changes, a possible QEMU IMSIC device-tree omission, and
standard-fd reuse when stdin is closed.

## Known boundaries

No release-blocking defect was found. Version 0.1.0 remains a development
milestone rather than a general-purpose VMM. In particular:

- only the RISC-V KVM direct-boot path is supported;
- AIA must be available as an in-kernel KVM irqchip;
- the machine has only platform RAM, UART, and the optional test device;
- host UART output is synchronous;
- the event backend is `poll` and has no timer or coroutine API;
- the big lock serializes guest-visible device state; and
- migration, snapshots, hotplug, PCIe, virtio, and IOMMU are not implemented.

These are candidate inputs to the next roadmap, not regressions against the
0.1.0 goal.
